## Mainnet

<Callout kind="warning" title="Not audited">
  The Spreadless contracts on Stellar mainnet have not been audited. They have
  been tested and reviewed internally, which is not a substitute. Use them at
  your own risk, and only with amounts you can afford to lose.
</Callout>

<Callout kind="warning" title="Router governance can replace pool code">
  The router owner can replace the code of the router and of **every pool
  registered with it, including pools created by third parties**, through
  `upgrade` and `upgrade_pool`. A pool's own owner cannot prevent this. The
  router owner can also pause any pool's swaps and deposits and set its protocol
  fee; withdrawals stay open while a pool is paused. Upgrades take effect
  immediately: there is no timelock. See [Governance](#governance) for who holds
  that key.
</Callout>

The router owner is currently a single hardware-wallet key. It is the only
account that can upgrade the router, upgrade a registered pool, pause or unpause

pool created that way, by anyone, is under this same control.

<Callout kind="note" title="SAC vs native">
  A **Stellar Asset Contract** wraps a *classic* asset, so it can only be held by
  an account with a trustline for it, and only its issuer can mint it. Native
  Soroban test tokens have neither constraint; anyone can mint them from the
  faucet and hold them without a trustline. This is why `SUSD` behaves differently
  from the other three throughout the app.
</Callout>

## Verifying an address

For any Stellar Asset Contract, `Asset(code, issuer).contractId(passphrase)` must
equal the token's contract address, a check you can run yourself to confirm a SAC
wraps the classic asset it claims to. Contract and transaction links throughout the
app point at Stellar Expert on this network so anything can be independently
inspected.
