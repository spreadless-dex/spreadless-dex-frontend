This is a practical reference to the pool contract methods the app uses, grouped
by read and write. Types are shown as the front-end sees them through the SDK
(`bigint` for on-chain integer amounts). Amounts are always in **raw units**,
scale by the token's decimals to get human values.

<Callout kind="note" title="Raw units">
  On-chain amounts are integers in the token's smallest unit. A `USDx` reserve of
  `1500000000` at 7 decimals is `150.0` tokens. LP shares (`SLP`) use 9 decimals.
</Callout>

## Read methods

These simulate only: no signature, no state change.

| Method | Returns | Purpose |
| --- | --- | --- |
| `get_tokens()` | `address[]` | The pool's assets, in canonical order. |
| `get_reserves()` | `i128[]` | Reserve of each token, same order as `get_tokens`. |
| `get_amp()` | `u32` | Effective amplification `A` (ramp-aware). |
| `paused()` | `bool` | Whether the pool is currently paused. |
| `total_supply()` | `i128` | Total `SLP` shares outstanding. |
| `balance(account)` | `i128` | An account's `SLP` share balance. |
| `get_owner()` | `address \| none` | The pool's owner. `none` once ownership was renounced. |

## Write methods

Each takes a signer (`to`) and enforces an on-chain minimum. All three follow the
same simulate-for-quote, submit-with-floor pattern.

### `swap_exact_in`

Sell an exact amount of one token for as much of another as the curve allows.

```ts
swap_exact_in({
  to,          // recipient + signer
  token_in,    // address of token being sold
  token_out,   // address of token being bought
  amount_in,   // bigint, raw units of token_in
  min_out,     // bigint, on-chain floor; revert if output < this
}) // → bigint  (token_out received)
```

### `deposit`

Add liquidity. `amounts_in` is indexed by canonical token order; single-sided
means one non-zero slot and zeros elsewhere.

```ts
deposit({
  to,          // recipient of LP + signer
  amounts_in,  // bigint[], one entry per pool token
  min_lp_out,  // bigint, floor on LP minted; revert if fewer
}) // → bigint  (SLP shares minted)
```

### `withdraw_one_token`

Burn LP shares and exit entirely into one chosen asset.

```ts
withdraw_one_token({
  to,             // recipient of token_out + signer
  lp_amount,      // bigint, SLP to burn (9 decimals)
  token_out,      // address of asset to receive
  min_amount_out, // bigint, floor on payout; revert if less
}) // → bigint  (token_out received)
```

## Owner methods

Only the current owner can call these. Ownership uses a two-step transfer: an
offer with an expiry ledger, then an accept by the recipient. See
[Pool Ownership](/docs/guides/pool-ownership) for the flow in the app.

| Method | Effect |
| --- | --- |
| `set_amp_ramp({ target_factor, duration })` | Moves `A` linearly from its current value to the target over `duration` seconds. `0` applies at once. |
| `set_swap_fee(fee)` | Sets the swap fee. |
| `pause()` / `unpause()` | Halts or resumes trading and deposits. |
| `transfer_ownership({ new_owner, live_until_ledger })` | Offers the pool to `new_owner` until the given ledger. `0` cancels an open offer. |
| `accept_ownership()` | Called by the offered address. This is the moment ownership moves. |
| `renounce_ownership()` | Removes the owner for good. Refused while an offer is open. |

<Callout kind="note" title="No pending getter">
  The contract does not expose the pending recipient of an open offer. The app
  keeps the offers it sent in the browser and shares them through an invite link.
</Callout>

## Quoting

The front-end never trusts a bare on-screen number. Before every write it runs the
same call with the floor set to `0` to read the exact quote, then re-submits with
the floor set from that quote minus tolerance. The read-only quote helpers wrap
this:

- `quoteSwapExactIn` → `{ amountOut, networkFeeXlm }`
- `quoteDepositSingleSided` → `bigint` LP out
- `quoteWithdrawOneToken` → `bigint` token out

<Callout kind="warning" title="Result unwrapping">
  On a failed simulation the SDK returns a Rust-style `Err` object rather than
  throwing. The app normalises these (`unwrapResult`) so a failed quote surfaces a
  real error instead of leaking `[object Object]` into the UI. If you integrate
  directly, handle the `Result` type; don't assume `.result` is always a value.
</Callout>

For how the floors are computed and enforced, see
[Slippage & Safety](/docs/protocol/slippage-and-safety). For contract IDs and the
token set, see [Deployments & Network](/docs/protocol/deployments).
